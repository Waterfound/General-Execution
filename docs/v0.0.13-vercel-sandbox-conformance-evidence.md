## Failure-domain discovery

### Direct `python3.13` Sandbox — first attempt

The original fixed command used editable installation with `--no-build-isolation`. The direct Python image did not already contain the required `setuptools.build_meta`, so package installation failed before tests.

This was an environment failure, not a General Execution regression.

### Direct `python3.13` Sandbox — second attempt

Allowing normal PEP 517 build isolation fixed package installation. `compileall` then passed, but pytest collection failed because the direct image did not contain the native `_sqlite3` extension required by General Execution's durable SQLite stores.

Again, this was an environment incompatibility rather than a failed General Execution test.

### `node24` Sandbox probe

The `node24` image contained a system Python 3.9.25 with working SQLite 3.40.0. Python 3.9 is below General Execution's declared `>=3.11` requirement.

The image's Amazon Linux package repositories exposed Python 3.11, 3.12, and 3.13 packages. The final bounded runner therefore provisions Python 3.13 explicitly instead of depending on the image's system Python.
