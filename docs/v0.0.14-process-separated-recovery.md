# v0.0.14 — Process-Separated Cold Recovery

## Goal

Raise the cold-recovery evidence boundary from API separation to interpreter-process separation.

v0.0.12 proves that the resume API accepts only durable store paths. v0.0.14 additionally runs preparation and resume in two separate Python interpreter processes so no Python object can survive from the preparation interpreter into the recovery interpreter.

## Worker protocol

`general_execution.process_worker` exposes two fixed QA phases:

```text
prepare
resume
```

The worker does not accept arbitrary commands or workload code. It only invokes the bounded v0.0.12 reference rehearsal operations with filesystem paths.

Each worker emits one canonical JSON object containing:

- phase;
- process token;
- PID and parent PID;
- bounded protocol payload;
- payload digest.

## Harness

`run_process_separated_cold_recovery(...)` uses `sys.executable -m general_execution.process_worker` with `subprocess.run(..., shell=False)`.

The preparation interpreter is waited for and reaped before the resume interpreter is launched.

The resume worker receives only:

- capacity-store path;
- recovery-context-store path;
- provider-registry path;
- terminal rehearsal mode.

It receives no serialized Spec, registry, plan, Session, runner object, authorization, recovered lease, provider key, or preparation receipt.

## Process evidence vs protocol identity

Process evidence is intentionally non-canonical. PIDs and random per-process tokens prove distinct worker lifetimes and naturally differ between runs.

The underlying v0.0.12 cold-recovery report remains canonical. Repeating the same protocol inputs in fresh directories must reproduce the same:

- cold report digest;
- durable recovery-context digest;
- physical outcome digest.

Therefore the system distinguishes:

```text
process evidence = execution-specific
protocol evidence = deterministic
```

## Authority boundary

The process harness launches only the fixed General Execution QA worker module. It is not a general command runner and adds no workload-execution authority.

Physical completion still does not submit the logical Session result automatically.

## Conformance bank

Tests cover distinct prepare/resume worker identities, direct-child process binding, reconstructed-context identity across the process boundary, completed-result separation, timeout without logical result, and deterministic protocol digests despite non-deterministic process tokens.

## Evidence boundary

This milestone provides the mechanism and conformance bank for process-separated recovery. The branch still requires execution of that bank in a complete Python runner before process-separation evidence can be claimed as observed rather than designed.

The full historical repository regression also remains an independent admission gate.

## Next boundary

After successful process-separated execution, local recovery architecture is effectively at its evidence ceiling. The next material gains should come from:

1. executing the full historical regression on the complete stacked line;
2. exercising a real external provider/host transport with the same reattachment contract;
3. multi-process or multi-host contention evidence where appropriate.

Additional restart-state semantics should not be added without new evidence revealing a concrete gap.
