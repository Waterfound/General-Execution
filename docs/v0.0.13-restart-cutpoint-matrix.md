# v0.0.13 — Restart Cut-Point Matrix

## Goal

Prove that each durable interruption point in the cold-recovery protocol converges to one explicit safe state rather than relying on timing or an assumed uninterrupted coordinator.

## Canonical cut points

The reference matrix walks the same physical attempt through six durable states:

```text
context_only
  -> capacity_committed
  -> provider_running
  -> terminal_persisted
  -> reconciliation_planned
  -> reconciled
```

Each cut point is inspected from the durable stores rather than from transient control flow.

## Safe dispositions

| Cut point | Required disposition | Canonical meaning |
| --- | --- | --- |
| `context_only` | `orphan_context` | Context exists, but no active capacity head exists. No work is recoverably active. |
| `capacity_committed` | `remain_unknown` | Lease is active but provider identity is absent; `not_found` cannot release or retry. |
| `provider_running` | `keep_running` | Provider identity exists and running status preserves occupancy. |
| `terminal_persisted` | `terminal_pending_reconciliation` | Terminal provider evidence is durable, but capacity remains occupied until reconciliation. |
| `reconciliation_planned` | `terminal_plan_reproducible` | Volatile reconciliation plan can be discarded and deterministically re-derived without store mutation. |
| `reconciled` | `reconciled` | Reconciliation CAS is the only step that removes the active lease. Provider terminal state remains durable. |

## Plan-loss boundary

The matrix deliberately computes the reconciliation plan after terminal persistence and then treats that plan as lost volatile state.

A second inspection must reproduce the exact same physical outcome and exact same reconciliation-plan digest from the durable terminal provider record and current capacity/context stores.

Planning itself must not mutate either durable capacity or provider state.

Therefore:

```text
terminal persistence != capacity release
reconciliation planning != capacity release
only canonical reconciliation CAS releases capacity
```

## Duplicate-execution boundary

At `capacity_committed`, provider lookup returns `not_found`. This remains inconclusive. The matrix does not authorize retry, fabricate transport failure, or release the lease.

At `provider_running`, the same physical authorization remains active. No second physical attempt is created.

These constraints preserve the one-active-canonical-attempt rule across restart cut points.

## Deterministic report

`RestartCutPointMatrixReport` requires the canonical six-point ordering and validates cross-point invariants, including:

- terminal-persisted and plan-reproduced states use the same capacity head;
- provider terminal record is unchanged by reconciliation planning;
- the reconciliation plan digest reproduces exactly after volatile loss;
- final reconciliation leaves zero active leases.

Fresh directories with identical protocol inputs must produce the same report digest.

## Authority boundary

The matrix is recovery QA. It does not authorize new execution, decide application correctness, integrate outputs, approve releases, or submit logical results.

## Evidence boundary

The repository includes a dedicated conformance bank for every cut point and cross-point invariant. This milestone does not itself establish that the entire historical repository suite has run successfully in a complete runner environment.

## Next boundary

Once cut-point semantics are frozen, the remaining high-value local evidence step is **process-separated cold recovery**: preparation in one Python process, complete process exit, and recovery in a new Python process that receives only durable store paths. After that, further confidence depends primarily on full-stack regression and real provider/host evidence rather than additional recovery semantics.
