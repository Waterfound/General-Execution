# v0.0.2 — Provider-neutral Adapter Contract

## Boundary

General Execution does not launch provider work itself. It creates an immutable `AdapterDispatchRequest` from an exact `ExecutionSpec`, registry, plan, runner, and running Session. An external provider returns a `ProviderObservation`; the coordinator admits it only when every bound identity reproduces exactly.

```text
ExecutionSpec + Registry + Plan + Session
              -> AdapterDispatchRequest
              -> external provider
              -> ProviderObservation
              -> AdapterReceipt + InvocationBundle
              -> ledger provenance
```

## Identity separation

A logical `ExecutionSession.session_id`, General Execution `invocation_id`, and external `provider_invocation_id` are separate namespaces. Provider retries or replicas therefore need not redefine the logical Session.

## Evidence admission

The reference contract proves request reconstruction, provider-response digest binding, evidence binding, and exact result/session matching. A completed provider observation means only that bounded execution completed; domain verification and integration remain outside General Execution.

## Ledger record

Accepted invocations are recorded as four consecutive events:

```text
ADAPTER_DISPATCH
PROVIDER_OBSERVATION
ADAPTER_RECEIPT
ADAPTER_RESULT
```

`InvocationRecord` binds the bundle digest to the event range and recorded ledger head.

## Local gate

Development gate for v0.0.2: 36/36 local tests GREEN plus `compileall` GREEN. The published conformance tests intentionally cover the protocol surface with a smaller neutral suite.
