# v0.0.4 — Capacity & Lease Semantics

## Goal

Make `RunnerCapabilities.max_parallelism` an executable runtime invariant before any concrete remote transport is added.

## Capacity state

Each runner has one canonical `RunnerCapacityState`. Its identity binds the runner capability digest, `max_parallelism`, generation, predecessor-state digest, and the append-only sequence of reserve/release transitions.

A transition is proposed against one exact `expected_state_digest` and can be committed only while that digest is still the canonical head. Two proposals created from the same snapshot therefore cannot both become the next canonical state: accepting one changes the head and makes the other proposal stale.

The persistence layer used by a future transport must preserve that compare-and-swap rule atomically. General Execution defines the state-transition contract; it does not provide storage itself.

## Capacity lease

A committed reservation produces a `CapacityLeaseGrant` bound to:

- runner ID and capability digest;
- deterministic slot index;
- logical Session ID and attempt;
- physical authorization ID and digest;
- invocation ID and physical-attempt ordinal;
- predecessor invocation ID and predecessor receipt digest for retries;
- source capacity-state digest;
- committed transition digest, state digest, and generation.

Grant verification replays the capacity state through the grant's committed generation and checks the exact transition digest and committed state digest, rather than merely checking that a similar lease is active.

Slots are selected deterministically from `0 .. max_parallelism-1`.

## Canonical occupancy

A runner can never have more active canonical leases than its declared `max_parallelism`.

One logical Session attempt may have only one active canonical physical lease at a time. This prevents concurrent retry proposals from both becoming canonical even when free runner capacity is greater than one.

## Release

Capacity leaves the active set only through an explicit transition. Two release paths exist:

1. an admitted terminal physical outcome from v0.0.3;
2. explicit revocation of the logical Session that owns the lease.

A `CapacityReleaseGrant` is verified against the exact committed release transition and state generation.

There is no wall-clock expiry in the core protocol. An external policy may decide that a Session should be revoked, but the capacity recovery remains an explicit state transition.

## Retry ordering

Physical attempt `N+1` may reserve capacity only after physical attempt `N` has a canonical release whose receipt digest equals the predecessor digest carried by the retry authorization and the resulting capacity lease.

```text
physical N
  -> terminal non-completed outcome
  -> receipt Rn
  -> capacity release bound to Rn
  -> physical N+1 lease binds invocation N + Rn
```

A completed predecessor is not a retry source. Because predecessor bindings are stored in the lease itself, `verify_capacity_state` can revalidate retry ordering from the capacity state alone; changing a retry lease to point at another receipt makes replay fail.

## Replay

`verify_capacity_state` reconstructs the state from runner genesis by replaying every transition and checking each predecessor digest, slot assignment, active occupancy, release reference, and retry predecessor binding.

Reserve/release transitions can also be appended to the ordinary execution ledger as `CAPACITY_RESERVED` and `CAPACITY_RELEASED` events.

## Targeted local conformance

The final v0.0.4 candidate passed **17/17 targeted tests** covering capacity exhaustion, multi-slot allocation, stale reservation/release rejection, release ordering, retry ordering, Session revocation, competing retries, execution-context binding, state replay, ledger recording, exact lease/release grant provenance, and tampered retry-predecessor replay rejection. `compileall` also passed locally.

## Next boundary

The next high-value milestone is durable-head and restart recovery: persist/reload canonical capacity state, replay it after coordinator restart, and reconcile an in-flight lease without inventing a physical outcome.
