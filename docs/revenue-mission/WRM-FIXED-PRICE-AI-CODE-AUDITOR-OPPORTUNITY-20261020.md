## Smallest admissible delivery shape

If the human qualification gate is cleared and the buyer accepts the proposal, the initial assessment should be constrained to:

1. **Immutable scope:** one named repository or exported snapshot at an agreed commit SHA; explicitly listed deployment/configuration artifacts.
2. **Read-only access:** least-privilege repository and configuration visibility; no production write permission, secret copying, account installation, or unsupervised deployment.
3. **Acceptance artifact:** concise report with exactly five prioritized risks, evidence locations, exploit/failure path, confidence, affected asset, recommended mitigation, and verification step.
4. **Architecture view:** current trust boundaries, identity/authorization flow, data classes, external services, deployment path, and unresolved unknowns.
5. **Prioritized plan:** critical before release, high next, optional hardening; effort estimates labelled as estimates.
6. **Exit review:** 30-minute walkthrough only if included in the funded milestone.
7. **Evidence handling:** no credentials or customer data in the report; redact sensitive paths and preserve source hashes privately.
8. **Stop conditions:** scope drift, missing authority, inaccessible evidence, unsafe testing request, unpaid bespoke work, or pressure to claim compliance without proof.

No penetration testing, code modification, compliance certification, production deployment, or remediation implementation should be implied in the USD 500 assessment unless explicitly funded and separately authorized.
