# WRM — Public Website Migration Validation Screen — 2026-10-16

Status: **CANDIDATE_KILLED / SERVICE_DEMAND_OBSERVED / READ_ONLY_DIFFERENTIATION_FALSIFIED / NO_PRODUCT_SELECTED**

This dossier tests one narrow job-to-be-done using public evidence only. It is not customer validation, a migration audit, SEO advice, quantified ROI, willingness-to-pay for Waterfound, or revenue.

## Narrow buyer and job

**Potential payer:** owner, agency, or ecommerce operator immediately before or after a CMS/domain migration.

**Job:** compare an old/live site with a staging/new site and produce a factual exception report for missing URLs, broken redirects, dropped content or media, metadata/canonical changes, and rendering differences—without CMS credentials or production writes.

The candidate was intentionally restricted to public/read-only verification. Remediation, analytics interpretation, CMS operation, private staging access, and ranking recovery were excluded.

## Falsification result

The paid problem is real, but the proposed read-only product is not differentiated:

- the core public evidence—URL status, redirects, metadata, crawl depth, page structure, raw/rendered content, and change history—is already produced by mature tools;
- URL remapping across changed structures is already an explicit Screaming Frog migration workflow;
- the paid scopes ask for human implementation, correction, CMS-specific verification, analytics/SEO interpretation, or recovery, rather than a bare exception report;
- a new Waterfound crawler or report generator would reproduce incumbent capability rather than answer a missing commercial predicate.

Therefore the candidate hits the kill criteria before build:

1. **direct-substitute parity:** incumbents already compare crawls and mapped staging/live sites;
2. **service-dominant demand:** observed budgets include migration execution and remediation;
3. **private-access dependency:** the residual valuable checks—forms, analytics, CMS fields, private staging, transactions, and conversions—often require credentials or operator judgment;
4. **no Waterfound WTP evidence:** no buyer has requested, tried, or paid for a Waterfound report.

## Evidence classification

- **Capability evidence:** public sources are sufficient to define the job and identify direct parity without implementation.
- **Observed outcome:** four buyer scopes show migration-QA demand; six substitute classes cover the read-only core.
- **Competitive differentiation:** falsified for generic old/new crawl comparison and migration exception reporting.
- **Demand evidence:** service-category intent only.
- **Waterfound willingness-to-try / WTP:** none.
- **Revenue:** USD 0.

## Decision and posture

**Kill:** generic public-site migration parity report, old/new crawl diff, broken-link/media checklist, and read-only migration evidence memo.

Do not build a crawler, dashboard, screenshot-diff service, SEO checklist, scheduled monitor, or URL-mapping engine for this hypothesis.

A future migration candidate may re-enter only if public evidence shows a narrowly repeated decision that the incumbents cannot produce and that does not depend on remediation, credentials, analytics interpretation, or private staging access.
