# WRM-T1 — Representative workflow event evidence (candidate)

Status: candidate-only research contract. This document does not authorize execution, alter authority, or establish economic ROI.

## Measurement boundary

A representative workflow requires an explicit intent event, a terminal event if observed, a stable workflow identifier, source-linked evidence, and a declared class of workflow. A GitHub pull-request creation timestamp is not automatically the intent timestamp; a merge timestamp is not automatically the end of the broader mission.

Record machine transitions, process invocations, genuinely required interventions, observed human-active intervals, retries, rework, recovery, and provenance item identities when these facts are independently observable. Preserve raw event references and distinguish a missing event from a verified zero.

## Completeness

An event count is exhaustive only when the observer has a bounded, source-supported completeness attestation for that event class and observation window. Otherwise its count and derived rate remain unknown (null). Deduplicate by source event ID. Provenance coverage requires a justified expected-item denominator; autonomous resolution rate requires an observed opportunity denominator. Neither may be inferred from a single successful demonstration.

## Comparable discipline

Only naturally occurring, materially matched workflows can support a savings delta. Match scope, terminal outcome, environment, and observation method; record differences and conservative lower bounds. Do not invent a manual baseline, infer human minutes from wall-clock time, or translate recovery capability into avoided losses.

## Next admissible implementation

Build a read-only, provider-neutral event adapter that checks evidence references, explicit completeness attestations, non-overlapping observed human-active intervals, unique identities, and terminal chronology. Feed the canonical value-proof projector without triggering work or creating authority. Validate with synthetic fixtures clearly labeled non-customer and collect real observations only from already-authorized workflows.
