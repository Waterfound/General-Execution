## Exact findings

### 1. Production build is blocked by undeclared shared types

**Evidence**

- `src/components/ChatInput.tsx` uses `Message[]` and `FilePreview[]`, but defines neither type and imports neither.
- `src/components/MainChatSection.tsx` initializes `useState<Message[]>`, but does not define or import `Message`.
- The immutable tree contains no shared type declaration file providing these names.

**Impact**

TypeScript cannot resolve the identifiers during type checking, so a production build should fail before deployment.

**Fix**

Create one shared module such as `src/types/chat.ts` exporting `Message` and `FilePreview`; import the types into all three consumers. Add a CI command that runs the production build.

**Effort:** small.

### 2. Core icon-only controls lack accessible names

**Evidence**

- `src/components/ChatHeader.tsx`: phone, video, and sidebar-toggle buttons contain only icons.
- `src/components/LeftSidebar.tsx`: profile, chats, groups, contacts, calendar, and settings controls contain only icons.
- `src/components/ChatInput.tsx`: attachment, emoji, and file-removal controls contain only icons.
- These call sites provide no `aria-label` or visible text.

**Impact**

Screen-reader users cannot reliably identify key actions. Tooltip-only remediation would also be insufficient for accessible naming.

**Fix**

Give each control a durable accessible name, and expose toggle state with `aria-expanded` or `aria-pressed` where applicable.

**Effort:** small.

### 3. Several visually actionable controls are inert

**Evidence**

- `src/components/ChatHeader.tsx`: phone and video buttons have no action.
- `src/components/LeftSidebar.tsx`: Settings and Logout menu entries have no action.
- `src/components/RightSidebar.tsx`: Report and Delete Chat History buttons have no action.

**Impact**

The UI presents production-looking actions that cannot complete their stated job. This is a direct broken-button/production-readiness issue.

**Fix**

Either implement each action with explicit success/failure state or remove/disable it with honest “not available” messaging until supported.

**Effort:** small to medium, depending on backend requirements.

### 4. The primary layout has no bounded mobile behavior

**Evidence**

- `src/app/page.tsx` always renders the left navigation, a `w-1/4` chat list, and the main chat area; the right `w-1/4` panel can be added.
- `ChatListSidebar` and `RightSidebar` use fixed fractional widths without responsive breakpoints or a mobile navigation state.
- The main shell uses `h-screen` with no small-viewport or safe-area treatment.

**Impact**

On narrow screens, multiple permanent columns compress the central conversation and controls, risking overflow and unusable tap targets.

**Fix**

Adopt breakpoint-specific navigation: one primary pane on small screens, drawers/sheets for secondary panes, and `min-w-0`/overflow constraints. Verify at representative mobile widths.

**Effort:** medium.

### 5. Uploaded preview object URLs are not cleaned up after sending

**Evidence**

- `src/components/ChatInput.tsx` creates one `URL.createObjectURL` per selected file.
- URLs are revoked only when a file is removed before sending.
- On send, previews move into message state and the selected list is cleared; no later cleanup revokes those URLs.

**Impact**

Repeated attachments retain browser resources for the lifetime of the page, creating avoidable memory growth.

**Fix**

Define ownership for preview URLs and revoke each URL when its message/file is removed or when the owning component unmounts. Do not revoke while a rendered preview still needs it.

**Effort:** small.

### 6. Shipped metadata remains create-next-app boilerplate

**Evidence**

`src/app/layout.tsx` exports:

- title: `Create Next App`
- description: `Generated by create next app`

**Impact**

Search results, link previews, and browser surfaces misidentify the product; this directly fails the requested SEO/metadata review category.

**Fix**

Replace with product-specific metadata and add canonical/Open Graph fields only when verified values exist.

**Effort:** small.
